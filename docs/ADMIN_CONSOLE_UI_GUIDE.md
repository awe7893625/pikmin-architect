# Admin Console UI 使用指南

## 概述

Admin Console 是一個授權管理後台，用於管理所有授權碼、查看使用狀態、產生新授權，以及直接授權裝置。此後台為 production 可用，但必須通過三道門保護才能訪問。

## 安全機制（三道門）

Admin Console 僅在同時滿足以下條件時才「存在」：

1. **ENABLE_ADMIN_CONSOLE === "1"**（環境變數）
2. **每個 request header 必須帶：`x-admin-key: <ADMIN_KEY>`**
3. **production 也允許，但必須手動開 ENABLE_ADMIN_CONSOLE（預設關閉）**

任一不符 → 404（不暴露存在性）

## 環境變數設定

在 Vercel Dashboard 或本地 `.env` 檔案中設定：

```bash
# 啟用 Admin Console
ENABLE_ADMIN_CONSOLE=1

# Admin Key（請使用強密碼）
ADMIN_KEY=your-strong-admin-key-here
```

⚠️ **重要**：請勿將 `ADMIN_KEY` 寫入前端檔案或 Git 倉庫。

## 訪問方式

1. 打開瀏覽器，訪問：`https://your-domain.com/admin`
2. 首次訪問時，系統會要求輸入 Admin Key
3. Admin Key 會保存在瀏覽器的 localStorage 中（僅本地，不會上傳到伺服器）

## 功能說明

### 區塊 1：授權總覽

顯示四個統計數字卡片：

- **總授權數**：已產生的所有授權碼總數
- **已使用授權數**：已經被激活使用的授權碼數量
- **尚未使用授權數**：尚未被激活的授權碼數量
- **管理員直接授權設備數**：通過「救命功能」直接授權的設備數量

### 區塊 2：授權清單

顯示所有授權碼的詳細資訊：

- **產生時間**：授權碼的創建時間（本地時間顯示）
- **授權類型**：年費授權 / 永久授權
- **來源**：付款 / 管理員手動
- **授權碼**：永遠遮罩顯示（例如：`PKM-9A0E****BBC1D`）
- **備註**：創建時添加的備註
- **使用狀態**：未使用 / 已使用
- **使用時間**：激活時間（若有）
- **綁定裝置**：顯示前 6 碼（例如：`Mac-8F2A…`）
- **操作按鈕**：
  - **重新綁定**：將授權碼從一個裝置轉移到另一個裝置

#### 搜尋功能

在搜尋框中輸入關鍵字，可以搜尋：
- 備註內容
- 裝置 ID（部分匹配）

#### 手機顯示

在手機上，授權清單會以卡片形式顯示，每個授權碼一張卡片，包含所有資訊和操作按鈕。

### 區塊 3：產生新授權

用於給朋友或客戶產生新的授權碼：

1. **選擇授權類型**：
   - 年費授權：有效期 1 年
   - 永久授權：永久有效

2. **填寫備註**（選填）：
   - 例如：「給朋友的授權」、「測試用授權」

3. **點擊「產生授權碼」**

4. **成功後會彈出 Modal**：
   - 顯示完整的授權碼（可複製）
   - 提示：「請把這組碼給對方，在 App 裡輸入即可」

#### 使用流程

**給朋友授權：**

1. 在「產生新授權」區塊選擇「永久授權」或「年費授權」
2. 在備註中填寫「給朋友的授權」或朋友的名字
3. 點擊「產生授權碼」
4. 複製授權碼
5. 將授權碼發送給朋友
6. 朋友在 App 中輸入授權碼即可激活

### 區塊 4：救命功能（作者自救）

如果你自己的電腦因為改版或測試被鎖住，可以在這裡救回來。

#### 使用流程

1. **取得你的 Device ID**：
   - 在 App 中查看（如果有顯示）
   - 或從 App 的日誌中查找
   - 或使用終端機命令：`idevice_id -l`（macOS）

2. **在「救命功能」區塊中**：
   - 貼上 Device ID
   - 填寫備註（選填，例如：`owner-recover`）

3. **點擊「直接授權此裝置（不需付款）」**

4. **成功後**：此裝置已由管理員直接授權，可立即使用

#### 永久自救流程

為了保證未來重構不會把自己鎖死，建議執行以下流程：

1. **在 /admin →「產生新授權」**：
   - 選擇：永久授權
   - 備註：`owner`
   - 點擊「產生授權碼」

2. **複製授權碼**

3. **在你自己的 App 裡激活**：
   - 打開 App
   - 輸入授權碼
   - 激活成功

4. **若未來又被鎖**：
   - 用 /admin →「裝置救援」
   - 貼上 deviceId
   - 直接授權

此流程必須在 KV-only 下成立，且 KV 不可用時明確 fail closed（不會給錯授權）。

## 操作說明

### 重新綁定裝置

**什麼時候用：**
- 用戶換了電腦或重新安裝系統
- 需要將授權從一個裝置轉移到另一個裝置

**操作步驟：**

1. 在授權清單中找到要重新綁定的授權碼
2. 點擊「重新綁定」按鈕
3. 在彈出的 Modal 中：
   - 確認授權碼（自動填入）
   - 輸入新的裝置 ID
4. 點擊「確認重新綁定」
5. 系統會提示：「確定要重新綁定嗎？原裝置將失去授權！」

**⚠️ 注意：**
- 重新綁定後，**原裝置將失去授權**
- 新裝置將獲得授權
- 此操作**不可逆**

### 查看授權使用狀態

在授權清單中，可以查看：

- **使用狀態**：未使用 / 已使用
- **使用時間**：如果已使用，會顯示激活時間
- **綁定裝置**：顯示綁定的裝置 ID（前 6 碼）

**搜尋已使用的授權：**
- 在搜尋框中輸入裝置 ID 的部分內容
- 或搜尋備註內容

## 錯誤處理

### 權限不足

如果看到 404 錯誤，可能是：
- `ENABLE_ADMIN_CONSOLE` 未設定為 `"1"`
- `x-admin-key` header 不正確
- Admin Key 輸入錯誤

**解決方法：**
- 檢查環境變數設定
- 重新輸入 Admin Key（清除 localStorage 後重新訪問）

### 系統不可用

如果看到「系統目前不可用，請稍後再試」：

- **原因**：KV 不可用（`KV_UNAVAILABLE`）
- **解決方法**：
  - 檢查 Vercel KV 配置
  - 確認 `KV_REST_API_URL` 和 `KV_REST_API_TOKEN` 已正確設定
  - 等待系統恢復

### 操作失敗

如果看到「操作失敗，請稍後再試」：

- **原因**：伺服器內部錯誤
- **解決方法**：
  - 檢查伺服器日誌
  - 確認 KV 連接正常
  - 重試操作

## 安全注意事項

1. **不要分享 Admin Key**：Admin Key 應該只有你一個人知道
2. **不要在公開場合使用**：避免在公共網路或不安全的環境中訪問 Admin Console
3. **定期更換 Admin Key**：建議每 3-6 個月更換一次
4. **監控授權使用**：定期檢查授權清單，確認沒有異常使用

## 常見問題

### Q: 為什麼看不到授權清單？

A: 可能是：
- KV 不可用（檢查環境變數）
- Admin Key 不正確
- `ENABLE_ADMIN_CONSOLE` 未啟用

### Q: 可以同時給多個裝置授權嗎？

A: 不可以。一個授權碼只能綁定一個裝置。如果需要給多個裝置授權，請產生多個授權碼。

### Q: 重新綁定後，原裝置還能用嗎？

A: 不能。重新綁定後，原裝置會失去授權。如果需要保留原裝置的授權，請產生新的授權碼給新裝置。

### Q: 如何查看完整的授權碼？

A: 在「產生新授權」成功後，Modal 中會顯示完整的授權碼。在授權清單中，授權碼會遮罩顯示（例如：`PKM-9A0E****BBC1D`），這是為了安全考慮。

### Q: 如何刪除授權碼？

A: 目前不支援刪除授權碼。如果需要停用某個授權碼，可以通過「重新綁定」將其綁定到一個不存在的裝置 ID，或聯繫技術支援。

## 技術細節

### API 端點

所有 Admin API 都位於 `/api/admin/*`：

- `GET /api/admin/licenses` - 列出所有授權
- `POST /api/admin/license/create` - 創建新授權
- `POST /api/admin/license/rebind` - 重新綁定裝置
- `POST /api/admin/device/grant` - 直接授權裝置

### 資料結構

**License 資料結構：**
```json
{
  "licenseKeyHash": "sha256 hash",
  "planType": "annual" | "lifetime",
  "createdAt": "ISO string",
  "issuedBy": "payment" | "admin",
  "note": "string",
  "boundDeviceId": "string | null",
  "activatedAt": "ISO string | null"
}
```

**Device 資料結構：**
```json
{
  "trialCount": 0,
  "licenseKey": "string | null",
  "activatedAt": "ISO string | null",
  "grantedBy": "admin" | null,
  "grantNote": "string | null",
  "grantedAt": "ISO string | null"
}
```

### License Index

系統使用 `license:index` 作為索引，儲存所有授權碼的列表：

```json
[
  { "licenseKey": "PKM-...", "createdAt": "ISO string" },
  ...
]
```

此索引用於快速列出所有授權，避免掃描整個 KV 空間。
