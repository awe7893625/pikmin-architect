## 🔄 授權流程現況

### 1. App 啟動流程

```
App 啟動
  ↓
DOMContentLoaded 事件觸發
  ↓
checkAuthStatus() 被調用（通過 window.webkit.messageHandlers.bridge）
  ↓
ContentView.swift checkAuthStatus() 執行
  ↓
POST /api/auth/check { deviceId }
  ↓
Server 檢查 devices Map（內存）
  ↓
返回 { trialCount, licenseKey, isActivated }
  ↓
ContentView.swift 判斷 isPaid = isActivated || (licenseKey != null)
  ↓
更新 UI（updateTrialStatus）
```

### 2. 試用次數消耗流程

```
用戶點擊 GO 按鈕
  ↓
run() 函數執行
  ↓
檢查 globalAuthState.isPaid（前端判斷）
  ↓
如果未付費，調用 /api/trial/use
  ↓
Server 檢查 devices Map（內存）
  ↓
扣除 trialCount
  ↓
返回 { trialCount }
```

### 3. 授權碼激活流程

```
用戶輸入授權碼
  ↓
POST /api/license/activate { deviceId, licenseKey }
  ↓
Server 檢查 licenses Map（內存）
  ↓
更新 devices Map（內存）
  ↓
返回 { success, licenseKey, activatedAt }
  ↓
清除 localStorage（favLocs, tpLocs）
  ↓
重新調用 checkAuthStatus()
```


**持久性：** ❌ 無，進程結束即遺失

## ⚠️ 問題點總結

### 1. Server-Side 問題

| 問題 | 影響 | 嚴重性 |
|------|------|--------|
| devices Map 使用內存存儲 | Vercel cold start/redeploy 後數據遺失 | 🔴 嚴重 |
| licenses Map 使用內存存儲 | 授權碼激活狀態遺失 | 🔴 嚴重 |
| orders Map 使用內存存儲 | 訂單記錄遺失 | 🟡 中等 |
| isActivated 判斷依賴內存數據 | 服務器重啟後判斷錯誤 | 🔴 嚴重 |

### 2. Client-Side 問題

| 問題 | 影響 | 嚴重性 |
|------|------|--------|
| ContentView.swift 雙重判斷 | `isPaid = isActivated \|\| licenseKey` 可能不一致 | 🔴 嚴重 |
| globalAuthState 可能用於功能判斷 | 如果 run() 使用，可能繞過 server 驗證 | 🔴 嚴重 |
| App 啟動時未強制等待 server 響應 | 可能使用緩存或錯誤狀態 | 🟡 中等 |

### 3. 數據一致性問題

| 場景 | 目前行為 | 正確行為 |
|------|---------|---------|
| Vercel redeploy | devices/licenses Map 清空，已激活設備變成未激活 | 應從持久化存儲讀取，狀態保持 |
| App 啟動時 server 無響應 | 可能使用 globalAuthState 緩存 | 應顯示錯誤，不可使用緩存 |
| 授權碼激活後立即查詢 | 可能讀取到舊的 devices Map | 應從持久化存儲讀取最新狀態 |

## 📊 授權判斷邏輯現況

### Server-Side（`website/server.js`）

**第 192 行：**
```javascript
const isActivated = !!device.licenseKey;
```

**問題：** 如果 `device` 不存在（服務器重啟後），`isActivated` 會是 `false`，即使設備已激活。

### Client-Side（`ContentView.swift`）

**第 1451 行（已修正）：**
```swift
let isPaid = isActivated  // 已修正為僅依賴 server 的 isActivated
```

**修正前：**
```swift
let isPaid = isActivated || (licenseKey != nil && !licenseKey!.isEmpty)
```

**問題：** 修正前的雙重判斷可能導致不一致。

## 🎯 重構目標

1. **持久化存儲：** 將 devices/licenses/orders 從內存 Map 改為持久化存儲（Vercel KV）
2. **單一真實來源：** Server 的 `isActivated` 是唯一判斷依據
3. **強制查詢：** App 啟動時必須等待 server 響應
4. **移除雙重判斷：** 前端不可使用 licenseKey 存在性判斷
5. **可觀測性：** 增加 log 和 debug 信息
