## ⚠️ 問題分析

### 核心問題

**目前授權系統使用 server-side in-memory Map 存儲授權狀態，在 Vercel 環境中會因以下情況導致數據遺失：**

1. **Cold Start（冷啟動）**：Vercel 函數長時間未使用後會關閉，重新啟動時所有內存數據清空
2. **Redeploy（重新部署）**：每次代碼更新部署時，服務器重啟，內存數據全部遺失
3. **多實例運行**：Vercel 可能同時運行多個實例，每個實例的內存 Map 是獨立的

### 影響

- ✅ **已授權設備**在服務器重啟後變成**未授權狀態**
- ✅ **試用次數**在服務器重啟後**重置為 3 次**
- ✅ **同一 deviceId**在不同時間查詢可能得到**不一致的結果**
- ✅ **授權碼激活狀態**在服務器重啟後**全部遺失**

## 🏗️ 目前架構分析

### 1. Server-Side 數據存儲（`website/server.js`）

```javascript
// ⚠️ 問題：內存存儲，服務器重啟後全部遺失
const devices = new Map(); // deviceId -> { trialCount, licenseKey, activatedAt, registeredAt }
const licenses = new Map(); // licenseKey -> { deviceId, paidAt, isValid, createdAt, activatedAt, planType }
const orders = new Map(); // orderId -> { planType, amount, status, licenseKey, createdAt, paidAt }
```

**存儲位置：**
- **物理位置**：Node.js 進程內存（RAM）
- **持久性**：❌ 無持久性，進程結束即遺失
- **跨實例**：❌ 每個實例獨立，無法共享

### 2. Client-Side 數據存儲（App）

```swift
// ContentView.swift - checkAuthStatus()
let isPaid = isActivated || (licenseKey != nil && !licenseKey!.isEmpty)
```

```javascript
// index.html - globalAuthState
var globalAuthState = {
    isPaid: false,
    remaining: 3,
    lastCheck: null
};
```

**存儲位置：**
- **物理位置**：App 內存（`globalAuthState`）+ 可能的 localStorage
- **持久性**：❌ 僅在 App 運行期間有效
- **可靠性**：❌ 不可作為授權判斷依據

### 3. 授權判斷邏輯

#### Server-Side（`/api/auth/check`）

```javascript
// ⚠️ 問題：依賴內存 Map，服務器重啟後 device 記錄遺失
const device = devices.get(deviceId);
const isActivated = !!device.licenseKey; // 如果 device 不存在，isActivated = false
```

#### Client-Side（`ContentView.swift`）

```swift
// ⚠️ 問題：雙重判斷邏輯，可能不一致
let isPaid = isActivated || (licenseKey != nil && !licenseKey!.isEmpty)
// 如果 server 返回 isActivated=false 但 licenseKey 存在，會誤判為已付費
```

## 🎯 Single Source of Truth 定義

### 正確的 Single Source of Truth

**Server 的持久化存儲中的 `isActivated` 狀態是唯一真實來源**

```
┌─────────────────────────────────────────┐
│  Single Source of Truth                 │
│                                         │
│  Server 持久化存儲                      │
│  ┌─────────────────────────────────┐   │
│  │ deviceId -> {                   │   │
│  │   licenseKey: "PKM-XXXX",       │   │
│  │   activatedAt: "2025-01-14...", │   │
│  │   isActivated: true              │   │
│  │ }                                │   │
│  └─────────────────────────────────┘   │
│                                         │
│  判斷規則：                             │
│  isActivated = (licenseKey != null &&   │
│                 licenseKey 在 licenses  │
│                 Map 中存在且有效)        │
└─────────────────────────────────────────┘
```

### 錯誤的判斷依據（必須移除）

1. ❌ **Client-side `globalAuthState.isPaid`**：僅為 UI 顯示用，不可作為功能判斷
2. ❌ **Client-side `localStorage`**：可被用戶修改，不可信任
3. ❌ **Client-side `licenseKey` 存在性檢查**：server 可能已重啟，licenseKey 在 server 端已遺失

## 📍 數據存放位置分析

### 目前實際存放位置

| 數據類型 | 存放位置 | 持久性 | 可靠性 | 問題 |
|---------|---------|--------|--------|------|
| `deviceId` | Mac Hardware UUID（設備端） | ✅ 永久 | ✅ 可靠 | 無 |
| `trialCount` | Server in-memory Map | ❌ 無 | ❌ 不可靠 | 服務器重啟後遺失 |
| `licenseKey` | Server in-memory Map（devices + licenses） | ❌ 無 | ❌ 不可靠 | 服務器重啟後遺失 |
| `isActivated` | Server 計算（`!!device.licenseKey`） | ❌ 無 | ❌ 不可靠 | 依賴內存數據 |
| `globalAuthState` | App 內存 | ❌ 無 | ❌ 不可靠 | 僅用於 UI，不可作為判斷依據 |

### 正確的存放位置（目標架構）

| 數據類型 | 存放位置 | 持久性 | 可靠性 |
|---------|---------|--------|--------|
| `deviceId` | Mac Hardware UUID（設備端） | ✅ 永久 | ✅ 可靠 |
| `trialCount` | **持久化存儲（KV/DB）** | ✅ 永久 | ✅ 可靠 |
| `licenseKey` | **持久化存儲（KV/DB）** | ✅ 永久 | ✅ 可靠 |
| `isActivated` | **持久化存儲計算結果** | ✅ 永久 | ✅ 可靠 |
| `globalAuthState` | App 內存（僅 UI 用） | ❌ 無 | ⚠️ 僅顯示用 |

## 🔧 修正方案

### 1. 修正 `isPaid` 判斷邏輯

#### ❌ 目前錯誤實現

```swift
// ContentView.swift - 錯誤：雙重判斷，可能不一致
let isPaid = isActivated || (licenseKey != nil && !licenseKey!.isEmpty)
```

#### ✅ 正確實現

```swift
// ContentView.swift - 正確：僅依賴 server 返回的 isActivated
let isPaid = isActivated  // server 的 isActivated 是唯一依據
```

### 2. 修正 App 啟動流程

#### ❌ 目前錯誤流程

```
App 啟動
  ↓
檢查 localStorage 或 globalAuthState（如果有）
  ↓
可選：向 server 查詢（可能失敗或超時）
  ↓
使用本地狀態或 server 狀態（不一致）
```

#### ✅ 正確流程

```
App 啟動
  ↓
必須：向 server 查詢授權狀態（阻塞或顯示載入中）
  ↓
等待 server 響應
  ↓
僅使用 server 返回的 isActivated 作為判斷依據
  ↓
更新 UI（globalAuthState 僅用於顯示）
```

### 3. 修正 Server 端判斷邏輯

#### ❌ 目前錯誤實現

```javascript
// server.js - 錯誤：依賴內存 Map，重啟後遺失
const device = devices.get(deviceId);
const isActivated = !!device.licenseKey; // 如果 device 不存在，返回 false
```

#### ✅ 正確實現（使用持久化存儲後）

```javascript
// server.js - 正確：從持久化存儲讀取
const device = await db.getDevice(deviceId); // 從數據庫/KV 讀取
if (!device) {
  // 新設備，創建記錄
  device = await db.createDevice(deviceId, { trialCount: 3 });
}

// 檢查授權碼是否有效（從持久化存儲驗證）
const license = await db.getLicense(device.licenseKey);
const isActivated = device.licenseKey && 
                    license && 
                    license.isValid && 
                    license.deviceId === deviceId;
```

## 💾 持久化方案

### 方案 1：Vercel KV（推薦，最簡單）

**優點：**
- ✅ 與 Vercel 無縫整合
- ✅ 自動擴展，無需管理
- ✅ 低延遲（邊緣網絡）
- ✅ 免費額度充足

**實施步驟：**

1. **安裝依賴**
```bash
npm install @vercel/kv
```

2. **在 Vercel 控制台設置 KV**
   - 前往 Vercel Dashboard → Storage → Create Database → KV
   - 記下 KV 的 URL 和 Token

3. **設置環境變數**
```
KV_REST_API_URL=https://your-kv.vercel.app
KV_REST_API_TOKEN=your-token
```

4. **修改 server.js**

```javascript
const { kv } = require('@vercel/kv');

// 設備數據結構
async function getDevice(deviceId) {
  const key = `device:${deviceId}`;
  const data = await kv.get(key);
  return data ? JSON.parse(data) : null;
}

async function setDevice(deviceId, deviceData) {
  const key = `device:${deviceId}`;
  await kv.set(key, JSON.stringify(deviceData));
}

// 授權碼數據結構
async function getLicense(licenseKey) {
  const key = `license:${licenseKey}`;
  const data = await kv.get(key);
  return data ? JSON.parse(data) : null;
}

async function setLicense(licenseKey, licenseData) {
  const key = `license:${licenseKey}`;
  await kv.set(key, JSON.stringify(licenseData));
}

// 修改 /api/auth/check
app.post('/api/auth/check', async (req, res) => {
  const { deviceId } = req.body;
  
  if (!deviceId) {
    return res.status(400).json({ error: 'deviceId 是必需的' });
  }
  
  // 從 KV 讀取設備數據
  let device = await getDevice(deviceId);
  
  // 如果設備不存在，創建新設備
  if (!device) {
    device = {
      trialCount: 3,
      licenseKey: null,
      activatedAt: null,
      registeredAt: new Date().toISOString()
    };
    await setDevice(deviceId, device);
  }
  
  // 檢查是否已激活（從 KV 驗證授權碼）
  let isActivated = false;
  if (device.licenseKey) {
    const license = await getLicense(device.licenseKey);
    isActivated = license && 
                  license.isValid && 
                  license.deviceId === deviceId;
    
    // 如果授權碼無效，清除設備上的 licenseKey
    if (!isActivated) {
      device.licenseKey = null;
      device.activatedAt = null;
      await setDevice(deviceId, device);
    }
  }
  
  res.json({
    trialCount: device.trialCount || 0,
    licenseKey: device.licenseKey || null,
    isActivated: isActivated  // 唯一真實來源
  });
});
```

### 方案 2：MongoDB Atlas（功能完整）

**優點：**
- ✅ 功能完整，支援複雜查詢
- ✅ 免費額度充足
- ✅ 可擴展性強

**實施步驟：**

1. **創建 MongoDB Atlas 帳號**
   - 前往 https://www.mongodb.com/cloud/atlas
   - 創建免費集群

2. **安裝依賴**
```bash
npm install mongodb
```

3. **設置環境變數**
```
MONGODB_URI=mongodb+srv://user:password@cluster.mongodb.net/dbname
```

4. **修改 server.js**

```javascript
const { MongoClient } = require('mongodb');

let db;
MongoClient.connect(process.env.MONGODB_URI)
  .then(client => {
    db = client.db();
    console.log('✅ MongoDB 連接成功');
  })
  .catch(err => {
    console.error('❌ MongoDB 連接失敗:', err);
  });

// 修改 /api/auth/check
app.post('/api/auth/check', async (req, res) => {
  const { deviceId } = req.body;
  
  if (!deviceId) {
    return res.status(400).json({ error: 'deviceId 是必需的' });
  }
  
  // 從 MongoDB 讀取設備數據
  let device = await db.collection('devices').findOne({ deviceId });
  
  // 如果設備不存在，創建新設備
  if (!device) {
    device = {
      deviceId,
      trialCount: 3,
      licenseKey: null,
      activatedAt: null,
      registeredAt: new Date()
    };
    await db.collection('devices').insertOne(device);
  }
  
  // 檢查是否已激活
  let isActivated = false;
  if (device.licenseKey) {
    const license = await db.collection('licenses').findOne({ 
      licenseKey: device.licenseKey 
    });
    isActivated = license && 
                  license.isValid && 
                  license.deviceId === deviceId;
  }
  
  res.json({
    trialCount: device.trialCount || 0,
    licenseKey: device.licenseKey || null,
    isActivated: isActivated  // 唯一真實來源
  });
});
```

### 方案 3：PostgreSQL（Vercel Postgres）

**優點：**
- ✅ Vercel 原生支援
- ✅ SQL 查詢功能強大
- ✅ 事務支援

**實施步驟：**

1. **在 Vercel 控制台創建 Postgres 數據庫**
   - 前往 Vercel Dashboard → Storage → Create Database → Postgres

2. **安裝依賴**
```bash
npm install @vercel/postgres
```

3. **修改 server.js**

```javascript
const { sql } = require('@vercel/postgres');

// 修改 /api/auth/check
app.post('/api/auth/check', async (req, res) => {
  const { deviceId } = req.body;
  
  if (!deviceId) {
    return res.status(400).json({ error: 'deviceId 是必需的' });
  }
  
  // 從 PostgreSQL 讀取設備數據
  let device = await sql`
    SELECT * FROM devices WHERE device_id = ${deviceId}
  `;
  
  // 如果設備不存在，創建新設備
  if (device.rows.length === 0) {
    await sql`
      INSERT INTO devices (device_id, trial_count, license_key, registered_at)
      VALUES (${deviceId}, 3, NULL, NOW())
    `;
    device = await sql`
      SELECT * FROM devices WHERE device_id = ${deviceId}
    `;
  }
  
  const deviceData = device.rows[0];
  
  // 檢查是否已激活
  let isActivated = false;
  if (deviceData.license_key) {
    const license = await sql`
      SELECT * FROM licenses 
      WHERE license_key = ${deviceData.license_key}
    `;
    isActivated = license.rows.length > 0 && 
                  license.rows[0].is_valid && 
                  license.rows[0].device_id === deviceId;
  }
  
  res.json({
    trialCount: deviceData.trial_count || 0,
    licenseKey: deviceData.license_key || null,
    isActivated: isActivated  // 唯一真實來源
  });
});
```

## 📝 總結

### 關鍵要點

1. **Single Source of Truth**：Server 持久化存儲中的 `isActivated` 是唯一真實來源
2. **App 啟動流程**：必須向 server 查詢，不可使用本地緩存
3. **判斷邏輯**：僅依賴 server 返回的 `isActivated`，不可雙重判斷
4. **持久化存儲**：必須使用 KV/DB，不可使用內存 Map

### 修正前後對比

| 項目 | 修正前 | 修正後 |
|------|--------|--------|
| 數據存儲 | 內存 Map | 持久化存儲（KV/DB） |
| 判斷依據 | `isActivated \|\| licenseKey` | 僅 `isActivated` |
| App 啟動 | 可選查詢 server | 必須查詢 server |
| 服務器重啟 | 數據遺失 | 數據保留 |
| 可靠性 | ❌ 低 | ✅ 高 |
